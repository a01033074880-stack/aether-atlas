# Editor / processor contract

Class `AetherAudioProcessor` in `Source/PluginProcessor.h`; editor class `AetherAudioProcessorEditor` in PluginEditor.h.

Public processor API:
```cpp
juce::AudioProcessorValueTreeState state;
std::atomic<float> inputMeterDb{-100}, outputMeterDb{-100}, gainReductionDb{0}, cpuPercent{0}, detectedPitchHz{0};
std::atomic<bool> analysisEnabled{true};
int readAnalysis(float* dest, int maximum) noexcept;
static juce::StringArray factoryPresetNames();
void loadFactoryPreset(int index);
juce::String currentPresetName() const;
juce::Result savePreset(const juce::File&);
juce::Result loadPreset(const juce::File&);
void toggleAB();
bool isSnapshotB() const noexcept;
void requestPanic() noexcept;
```

All UI parameters declared in `Source/Parameters.h` through `aether::parameterSpecs()`, returning a `const std::vector<ParameterSpec>&`. `ParameterSpec { const char* id; const char* name; float minimum, maximum, defaultValue, skew; const char* unit; const char* group; juce::StringArray choices; bool boolean; };`. Choices use integer normalized APVTS values; booleans use ButtonAttachment. Dotted IDs. `createParameterLayout()` free function in aether namespace. UI must use attachments and gestures; never modify DSP directly. Preset button dialogs use SafePointer, retained FileChooser, async launch. A/B and preset name are persisted in DAW state where possible.

Need exact parameter IDs/defaults from Source/Parameters.h/cpp, generated by controller before editor dispatch. UI supports all parameters, including advanced master/dither/mod controls (advanced/minimal view allowed). Order choice selects 24 lexicographic first-four-stage permutations; stage enable IDs spectral.enabled/modal.enabled/colour.enabled/space.enabled/master.enabled. Master fixed last. FX and Synth share same UI, header shows JucePlugin_Name. Mode settable; Synth variant defaults mode Synth. UI preview executable will capture main and minimal editor and verify window resizing. Value text should be short and units visible; no obscure internal implementation names in product UI.
